# Applywright operator and delegation rules

This is an independent repository. The current human grant makes Codex the main
project orchestrator, architect, integrator and final acceptor. Follow the parent
estate safety/credential rules and the latest dated operator steering. This file
does not grant writes in the hub, another worktree, or another brain/vault note.

## Delegate substantial work

- Use T3 native children as the normal work surface, through the existing
  **Applywright Native Review Broker**. Do not create another coordinator or timer.
- Before doing a substantial independent task in Codex, select the best qualified
  provider/harness and delegate a concrete owned output. Keep architecture, task
  decomposition, integration, difficult decisions and final acceptance in Codex.
- DSH/DeepSeek is the default implementation, test-authoring, bulk extraction and
  documentation worker. Its unlimited-agent policy remains; physical RAM, shared
  locks, claims and provider admission still apply. Preserve Estate's DSH defaults.
- Gemini is the lead visual-design author, through the qualified subscription
  Antigravity/agy route. Codex owns product direction and design acceptance. Use the
  current account catalogue; a new public model announcement is not access proof.
- Grok CLI/Build subscription is preferred for current research and primary-source
  verification. Muse/Wonder is suitable for long reading, synthesis and first-pass
  refutation after an actual contributor-OFF check. Jev is advisory for bounded
  closed-set classification/routing; it never authorizes an action.
- Native Codex Sol 6.1/xhigh/Standard provides independent review of grounding,
  process ownership, security and consequential changes. Its author must not be the
  implementation writer. Use Codex readers/subagents for work whose value justifies
  them; do not keep routine bulk work in Codex by default.
- Use High for routine Codex work and xhigh for difficult/security/consequential
  review; effort does not enlarge context. Keep Standard service tier for both.
- Claude Org API credits may support appropriate bounded work only through the
  approved direct API adapter/selected-variable loader and current shared accounting
  guard. The existing shared cap is USD190; spent and pending/encumbered usage must
  be known before a paid call. Unknown is not zero. Subscription and Org API routes
  are distinct; do not wake Claude Code/panes or substitute another billing route.
- Use useful work, not filler calls or token targets, to increase qualified provider
  use. Record actual model/harness, task/run IDs, outputs and exposed usage; missing
  cost/tokens/served identity remain UNKNOWN.

## Preserve current settings and ownership

- Fast and Ultrafast are OFF for Codex. Explicitly request Standard/default for new
  Codex children. Preserve each model's supported maximum context, effort, full
  access, accounts and MCPs. DeepSeek and other providers are not altered by this.
- Workers use new assigned worktrees and exact file sets; they are not alone and
  must preserve other edits. Workers never commit, self-merge, publish or accept.
- Core G1 owns tailor/refine and their tests; E2E owns its flow/owned-child helpers
  and tests. Research/design tasks must use disjoint proposal/evidence files until
  their implementation is separately assigned. Preserve frozen attempts and hashes.
- Only the operator integrates accepted source, commits named paths and pushes.
  Never use git add -A/add . or prune/archive someone else's worktree.
- Root coordinates the estate; Estate is the sole shared A/B publisher. This
  project's only eligible B note is brain/applywright-platform.md, coordinated with
  that publisher. Send other shared guidance as an owner publication patch.

## Admission and verification

- Fresh Windows4GiB and already-running Ubuntu names-only checks precede relevant
  Windows-origin launches. Never boot/shutdown WSL or close apps to force admission.
- SOURCE dispatch uses the approved released SH observation and separate actual
  native/provider lifetime admission. Tests/builds need the canonical heavy lock EX
  for their full lifetime. No unchanged busy loop, guard/slot/default bypass or
  linked-environment workaround. An actor's own denied scope stops there.
- Source workers author code/tests but execute no Node/test/build/native/browser
  phase while holding model SOURCE admission. The operator runs stopped candidates
  with exact before/after hashes, independent fixtures and meaningful assertions.
- Required integrated gates: node --test tests/ ; node --test server/lib server/provider ;
  node scripts/check.js. Preserve failures/skips. Add focused checks appropriate to
  the change. Native ownership and the isolated browser journey are separate gates.
- Interactive GUI uses admitted guarded estate-cua and one driver; never attach
  Johan's main Chrome. Product test profiles/DBs are separate from agent homes.
  Headless-agent CUA remains closed; a product test does not release that capability.
- Never read/copy/print secret stores, env/auth/token files or keys. Use approved
  named ambient variables/loaders or the tool's own sign-in. Missing auth fails
  closed; no keys in prompts, settings, reports or arguments.
- No PM2/fleet mutation, reserved-port binding, live-server restart or deployment
  follows from a source/test/benchmark result. A source-only pass, green mocks,
  compile-only DLL or docs push is not runtime or whole-mission completion.
